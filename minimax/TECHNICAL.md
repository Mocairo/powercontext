# 一页技术说明

本模块服务于局部代码修改：输入任务目标、关联规格与关键词，输出带路径、符号、版本和内容哈希的规格/代码/测试，以及已完成事项、待办和验证结果。

```text
规格 + 初始代码 + 固定测试
          ↓ 导入（文件/条目哈希与当前版本）
       真实 seekdb
          ↓ SQL 查询与关联选择
任务 → 当前上下文 ← PowerContext 持久任务状态
          ↓ 阶段 B 的真实 MiniMax 请求
     完整业务代码输出
          ↓ 路径/允许范围/语法检查
     独立 candidate 目录
          ↓ 同一套目标和回归测试
       证据 + 状态更新
```

**seekdb** 保存工程资料/索引并执行实际查询；数据库返回的资料内容参与上下文，不按任务名返回写死答案。资料带类型、源路径、规格编号或符号位置、版本/哈希与有效性信息。导入更新后只选当前有效内容，规格 v1→v2 实验验证旧规则不混入新要求。结构化规格关联和关键词检索覆盖小型工程，无需模型 embedding。

**PowerContext 1.4.1** 通过真实 SDK 显式 AtomicMemory 写入目标、阶段、完成项、待办、测试摘要和代码哈希。采用本演示独立 SQLite 持久后端，不需要任何模型。新进程创建新的客户端读取服务状态，将其用于后续上下文与下一步选择；JSON 证据仅供审计，不作为恢复状态的来源。状态保存摘要，详细测试日志单独留证据。

**MiniMax** 通过官方 OpenAI 兼容 Chat Completions 协议参与阶段 B 的代码修改。一次运行最多服务预检及生成两次调用，限制超时和输出。上下文包含真实检索来源及恢复状态，输出只接受允许业务文件的完整替换并生成差异；不允许修改固定验收测试。记录最终代码及脱敏调用数据，不记录认证头或私有推理文本。

**验证样例** 初始工单工具支持列出、负责人过滤和 id 升序。目标新增状态过滤、组合过滤、输入校验及空匹配处理。固定测试在初始版本表现为回归通过、目标因功能缺失失败；阶段 B 对模型修改结果复用同一测试集。阶段 A 保留未实现状态筛选的初始版本；阶段 B 由真实 MiniMax-M3.1-Flash 生成修改，同一套目标 20 项与回归 9 项全部通过，模型输出原样保存为 `demo/after/ticket_tool.py`。

**边界** 所有作品资产在 `minimax/`，运行依赖独立安装并由 lock 固定。每次演示独立运行目录隔离数据库和状态；重置仅处理带标记的单个目录。补丁限制不是恶意 Python 沙箱，模型代码执行应使用受控环境。真实调用遵循既有环境代理，SOCKS 支持纳入锁定依赖。首次连接失败与后续恢复保留独立证据；不保存私有推理文本。六项已有本地运行证据，平台提测与官方评分另行确认。
